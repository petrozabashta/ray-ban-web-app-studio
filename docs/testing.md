# Проверки и измерения

## Команды

- `npm run typecheck` — TypeScript в строгом режиме.
- `npm run lint` — ESLint.
- `npm test` — unit tests чистых функций чек-листа.
- `npm run test:browser` — пересобирает production build и запускает Playwright против `vite preview`.
- `npm run check` — все перечисленные проверки.

При первом запуске browser tests установите Chromium локально для Playwright: `npx playwright install chromium`. Это не устанавливает глобальный npm-пакет.

Browser tests проверяют основной сценарий, сохранение после перезагрузки, добавление и подтверждение сброса, явное сообщение при недоступном storage, стрелки и Enter на экране управления, viewport 600×600 и desktop 1000×800, локальный DEMO/MOCK видеосигнал через WebRTC loopback, декодирование кадров и очистку при остановке, явный отказ при отсутствии WebRTC и отсутствие вызова `getUserMedia`, загрузку Snake без ошибок и паузу его игрового цикла при скрытии страницы. Они также печатают начальное число запросов и переданные байты через Resource Timing. Тесты работают на production preview, не на dev server.

Чтобы вручную запустить браузерный DEMO/MOCK, выполните `npm run dev`, откройте Vite URL в Chrome, выберите **Тест видео DEMO/MOCK** и нажмите **Запустить локальный тест**. На экране виден синтетический источник и его локальный WebRTC-приёмник; кнопка остановки освобождает дорожки и peer connections. Видео остаётся внутри одной вкладки и не использует камеру, интернет-сервис или хранилище. Измеряется только частота показа на стороне браузера; сквозная задержка и работа Meta DAT не проверяются.

Официальный Meta Mock Device Kit может дополнительно тестировать SDK без физических очков: симулировать camera feed из файла H.265, permissions и display. Для него нужен нативный DAT-проект и подходящая среда iOS/Android; текущий браузерный тест не является заменой этому набору. См. [статус проекта](./project-state.md).

## Интерпретация startup budget

В текущих официальных материалах Meta для профиля устройства указаны: общая первая передача менее 300 KB, менее 15 начальных запросов, warm launch менее 2 секунд с 0 переданных байт, heap менее 128 MB и кадр 33 ms для панели 30 Hz. Fast-host browser test здесь измеряет первоначальные transfer sizes и запросы локального production preview; это не измеряет скорость радиоканала, медленный CPU очков, FCP/время полезного содержимого на устройстве или warm launch.

Значение `PerformanceResourceTiming.transferSize` включает размер передачи ресурса, доступный браузеру, с заголовками HTTP; оно отличается от размера файлов на диске и от суммы размеров gzip-файлов. Отчёт Playwright печатает фактическое число байт и запросов. Также проверяйте размер gzip JS при анализе bundle; это не подмена фактической сетевой передачи.

Контрольный локальный прогон 2026-11-03: 176,165 переданных байт и 3 начальных запроса; production bundle сообщает gzip JS 158.65 KB. Это снимок данного проекта, а не гарантия будущих сборок.

Если бюджет превышен, проверьте тяжёлые зависимости и их вклад в `dist/assets`, уберите неиспользуемые экспорты/медиа и повторите тест. Не снижайте пороги ради зелёного результата. Результат локального теста не доказывает производительность на очках.

## Что браузерные тесты не доказывают

Playwright не использует установленное расширение симулятора и не подключается к очкам. Визуальный D-pad, аддитивный контраст и запись WebM проверяйте вручную по [инструкции симулятора](./simulator.md). Совместимость, разрешения, отзывчивость и работу на реальном Meta Ray-Ban Display нужно отдельно подтвердить на устройстве.
